# 03: 撤回同意与个人数据清理

**What to build:** 用户能明确区分撤回云服务同意、清除本机数据和删除全部个人数据。撤回立即停止新增云请求，本地训练继续可用；删除全部个人数据必须联网确认，失败可重试，旧设备及旧队列不能让已删除数据复活。

**Blocked by:** 02 — 计划与训练记录可靠同步。

**Status:** ready-for-agent

本票落实拆票时新确认的规则：撤回同意与云端删除分开；不得声称已撤销在途请求。此规则取代父规格里尚待确认的候选描述，不修改父 issue。

- [ ] “我的”提供三个含义明确的独立操作；撤回后立即停止新增身份、同步及远程媒体请求，不能被重试定时器或网络恢复监听自动重新开启。
- [ ] 撤回同意不冒充云数据已删除；说明在途请求可能已执行，旧回调不得重新开启云服务或回填已清理的本地状态。重新启用云服务需再次主动同意。
- [ ] 撤回后仍能在明确授权的删除操作中联网删除本人云数据；该次授权仅用于删除，不顺带恢复常规同步或上传本地数据。
- [ ] 清除本机可离线执行；有进行中草稿或未同步数据时展示损失范围并二次确认。确认文案明确偏好及同意状态的处理范围，不能混淆为全端删除。
- [ ] 清本机覆盖本地计划、历史、草稿、队列及相应同步状态；旧任务/在途回调不得重新写回或上传已清数据。明确云端仍保留，重新启用同步可能下载既有云数据。
- [ ] 全部删除需联网、校验可信本人身份并二次确认；云端删除确认完成后才清本地，不影响其他用户或公共动作媒体。失败或中断不报成功，保留幂等重试及可理解的状态。
- [ ] 删除屏障覆盖所有写入路径，包括客户端直写、云函数、延迟请求和旧设备队列；不能只给新版本 UI 加检查。删除与并发写入交错、旧版直接写入也不能绕过屏障复活数据。
- [ ] 其他设备下次联网时识别旧数据失效并处理缓存，不把旧任务重新绑定为新数据上传。告知离线设备缓存无法即时远程物理擦除；删除后主动新建的数据可正常使用。
- [ ] 仅保留防复活必需的最小技术元数据，明确用途、范围和保存策略，向第04票提供真实隐私说明，不承诺所有技术痕迹均被擦除。
- [ ] 自动测试覆盖撤回后网络恢复/定时重试、在途回调、离线清本机、删除失败/响应丢失/重试、A删除不影响B、旧设备/旧版写入、删除与写入竞态及删除后重新使用。
