# 动作库接入 exercises-dataset 并展示标准动作

> 已由 `.scratch/common-exercise-catalog/` 的精选目录、分页缩略图与媒体同步任务取代；本文件保留为历史规格，不再作为当前动作库契约。

grilling 结论见 `docs/spec.md` 动作库节、`CONTEXT.md` 动作库侧、ADR-0007。本文是 `/to-spec` 产出的实现规格。

测试缝已与维护者确认：**新建动作目录纯模块**（无 `wx.*`、无 CloudBase）；`utils/domain.js` 不承担检索/归并；volume 口径不变。

---

## Problem Statement

训练者在动作库里只能看到约 30 条手写精选，详情是汉字占位，没有标准动作演示，也没有分步要领。打卡时无法对照动作轨迹。规格已指定数据源 `hasaneyldrm/exercises-dataset`，当前实现已由 `.scratch/common-exercise-catalog/` 的精选目录任务取代。

## Solution

历史规格曾计划把排除 cardio 后的全量动作文本精简打进主包；当前契约改为精确白名单的约 100–140 条精选常用动作。每个动作的「标准动作」= 180×180 分解 GIF（动作演示）+ 中文分步要领；JPEG 作动作库列表和打卡页缩略图及 GIF 失败占位。GIF/JPEG 上传 CloudBase 按需加载，详情按 GIF → JPEG → glyph 降级。动作库列表已显示 JPEG，今天/计划/记录清单仍不加载媒体。

## User Stories

1. 作为训练者，我想在无网时浏览全部非 cardio 动作，以便在健身房加练时不依赖网络。
2. 作为训练者，我不想在动作库里看到跑步、跳绳等 cardio，以便列表只服务力量训练。
3. 作为训练者，我想保留名字里带 stretch 的条目，以便热身/放松也能从库里加。
4. 作为训练者，我想用中文名搜索动作，以便快速找到常用动作。
5. 作为训练者，我想用英文原名搜索动作，以便按国际叫法检索。
6. 作为训练者，我想按目标肌群中文（如胸大肌）搜到动作，以便按刺激部位找。
7. 作为训练者，我想按部位中文（如腰腹）搜到动作，以便和筛选用语一致。
8. 作为训练者，我想按器械中文（如杠铃、史密斯）搜到动作，以便按手头器材找。
9. 作为训练者，我想用器械筛选桶缩小精选列表，以便在约 100–140 条常用动作里快速收窄。
10. 作为训练者，我想把曲杠、奥杠、六角杠算进「杠铃」桶，以便变体不会失踪。
11. 作为训练者，我想把杠杆器械、史密斯、腿举器械算进「器械」桶，以便「器械」筛选不是空的。
12. 作为训练者，我想在「自重」桶里看到辅助（assisted）动作，以便辅助引体等能被发现。
13. 作为训练者，我想用「其他」桶找到壶铃、弹力带、药球等，以便不单独开这些 pill 仍能筛到。
14. 作为训练者，我想用精选部位筛选（胸/背/肩/二头肌/三头肌/腿/腰腹/臀/复合动作）缩小列表，以便按产品分类找。
15. 作为训练者，我想器械筛选和部位筛选同时生效（AND），以便「自重 + 腰腹」能直接列出。
16. 作为训练者，我想在两维都选「全部」且无搜索词时看到完整精选目录，以便确认覆盖范围。
17. 作为训练者，我想在无匹配时看到空状态，以便知道该换关键词或筛选。
18. 作为训练者，我想列表标题显示中文名，以便扫列表时不用读英文。
19. 作为训练者，我想列表 meta 显示目标肌群中文和器械中文，以便不点进详情也能判断。
20. 作为训练者，我想在动作库列表看到 JPEG 缩略图并按 24 条分页，以便识别动作且不加载 GIF。
21. 作为训练者，我想点进详情看到中文名和英文副标题，以便对照国际名称。
22. 作为训练者，我想在详情里看到循环播放的分解 GIF，以便知道标准动作轨迹。
23. 作为训练者，我想在详情里看到中文分步要领，以便无网也能复习做法。
24. 作为训练者，我想在详情里看到中文目标肌群，以便确认刺激部位。
25. 作为训练者，我想在详情里看到部位标签，以便和筛选用语对上。
26. 作为训练者，我不想在详情里看到次要肌群和器械英文原值，以便弹层不被字段堆满。
27. 作为训练者，我想在详情里看到 `© Gym visual — https://gymvisual.com/`，以便来源交代清楚。
28. 作为训练者，我想 GIF 加载失败时退到示意图，再失败显示首字 glyph，以便媒体未上传或断网时详情仍能用。
29. 作为训练者，我想从计划 tab 打开动作库并把动作加入当前训练日，以便编排循环。
30. 作为训练者，我想从训练日编辑页打开动作库并加入该日，以便改某一天的动作清单。
31. 作为训练者，我想在打卡中打开动作库做临时加练，选中后回到打卡页，以便计划外补一组。
32. 作为训练者，我想加入计划的动作带上数据集 id、中文名和器械原值，以便 volume 和反查媒体都正确。
33. 作为练自重动作的训练者，我想加入计划时默认目标重量为 0，以便不把徒手动作写成 20kg。
34. 作为训练者，我想在打卡页每个动作旁看到示意图缩略图，以便当场认出动作。
35. 作为训练者，我想点缩略图打开和动作库相同的详情弹层（GIF + 要领），以便对镜时看演示而不跳页。
36. 作为训练者，我不想打卡页 8 个 GIF 一起自动播，以便省电省流量、界面不刷屏。
37. 作为训练者，我想无网打卡时仍能看缩略图失败后的 glyph 和本地要领（若目录在包内），以便演示挂了也不挡记组。
38. 作为训练者，我想旧场次（slug id）在打卡中查不到媒体时安静降级，以便历史草稿不崩。
39. 作为训练者，我不想今天页、计划清单、记录页出现 GIF，以便那些页面继续只展示名称。
40. 作为训练者，我想新装小程序后的演示计划（胸三/背二/肩腿）使用精选目录数字 id，以便从第一天就能打开演示。
41. 作为已经有旧计划的训练者，我想计划里的旧 slug 自动解析成数据集 id，以便加练和演示对得上，不用手改计划。
42. 作为训练者，我想记录趋势仍然按动作名聚合，以便换 id 不把历史曲线劈成两截。
43. 作为训练者，我想自重动作的容量仍按总次数计，判据是器械原值 `body weight`，以便「自重筛选」包含 assisted 时容量口径不变。
44. 作为产品维护者，我想文本字段精简后打进主包，以便离线检索不打云。
45. 作为产品维护者，我想丢掉十种语言的长说明，只留中文要领，以便主包远低于 2MB。
46. 作为产品维护者，我想实测裁剪后体积，超过 2MB 再分包，以便不赌包体。
47. 作为产品维护者，我想示意图和 GIF 走 CloudBase 而不是 GitHub 热链，以便国内可加载、也不把未授权媒体公开再分发。
48. 作为产品维护者，我想用构建脚本从上游 JSON 生成精简目录，以便以后更新数据集可重跑。
49. 作为产品维护者，我想原 30 条手译覆盖社区映射，以便常用动作中文名是人话。
50. 作为产品维护者，我想一对多英文名时绑定常规变体而不是史密斯机变体，以便种子计划语义稳定。
51. 作为产品维护者，我想在未配置云存储前缀时全库仍可搜可加，以便媒体上传可后做、不挡文本接入。
52. 作为产品负责人，我想个人自用先加载真实媒体并署名，以便这轮就能看到标准动作。
53. 作为产品负责人，我想商用上线前仍把 Gym visual 书面授权当阻塞项，以便不把克隆仓库当成授权。

## Implementation Decisions

- **数据源与范围**：`hasaneyldrm/exercises-dataset`。排除 `category`/`body_part` 为 cardio 的条目；名字含 stretch 的保留。约 1,295 条。
- **主键**：数据集 4 位数字字符串（如 `"0025"`）。计划项与 session 的 `exerciseId` 用它。旧 slug 经解析表转到数字 id。
- **动作条目形状**：`{id, name, nameZh, equipment, bodyPart, target, imagePath, gifPath, instructionSteps}`。`equipment`/`bodyPart`/`target` 存英文原值。`instructionSteps` 仅中文分步。不存 `muscle_group`、次要肌群、多语言说明、`created_at`。
- **中文名**：社区 `name_zh` 打底（去掉汉字之间的多余空格）；原 30 条手译覆盖。列表展示 `nameZh`，详情英文副标题用 `name`。

- **交付**：精选精简目录随主包发布，离线只读。JPEG/GIF 上传 CloudBase，路径写相对 `exercises/images|videos/...`，运行时拼 fileID 前缀。列表显示 JPEG 缩略图并按 24 条分页，详情按 GIF → JPEG → glyph 降级；前缀未配置则媒体 URL 为空。不热链 GitHub/jsDelivr，不把目录放云数据库。
- **动作目录模块（第二测试缝）**：纯函数，输入输出为普通对象/数组。至少暴露：按 id 查找（含 slug 解析）、搜索（关键词 + 器械桶 + 部位，AND）、器械桶归并、桶/器械/部位/目标肌群中文标签。页面只调这些函数，不在页面里复制归并表。
- **domain 模块**：不增加检索职责。`computeVolume` 仍只认 `equipment === "body weight"`。筛选桶把 `assisted` 归入「自重」**不得**改变这条判据。
- **器械筛选**：一行 6 桶：全部 / 杠铃 / 哑铃 / 绳索 / 器械 / 自重 / 其他。归并表见 `CONTEXT.md`。原值原样写入计划与 session。
- **部位筛选**：第二行 9 类 + 全部。`waist` 展示「腰腹」。两行 AND。
- **目标肌群展示**：固定中文表（pectorals→胸大肌 等 18 个非 cardio 枚举）。详情不展示次要肌群。
- **详情 UI**：可滚动弹层，动作库与打卡页复用同一组件。内容：中文名、英文副标题、GIF、要领、目标肌群、部位、署名；动作库入口带「加入」按钮，打卡页只看不选。
- **打卡页**：动作行内示意图；点开复用弹层。不自动播全部 GIF。用 `exerciseId` 反查目录拿媒体与要领，不把路径写入 session。
- **种子与迁移**：新种子计划使用数字 id 与目录中的 `nameZh`/`equipment`。读取已有计划时把已知 slug 解析成数字 id，并补当前中文名与器械原值（组数/目标不变）。记录趋势继续按动作名。
- **媒体加载失败**：GIF 错 → 示意图；再错 → 首字 glyph。
- **版权**：个人自用加载真实媒体并署名。商用上线前书面授权仍是发布阻塞项（不在本 spec 的实现任务内完成授权流程）。

## Testing Decisions

- 只测动作目录模块的**外部行为**（输入 → 返回的列表/条目/标签），不断言内部用数组还是 map、不断言文件如何生成。
- 覆盖：
  - 排除 cardio 后的规模与「无 cardio 部位」。
  - 器械桶归并（曲杠/史密斯/绳/assisted/壶铃→其他）。
  - 部位 `waist`→腰腹、目标 `pectorals`→胸大肌。
  - slug `bench-press`→`0025` 且中文名为手译「杠铃卧推」。
  - 搜索中英名；器械桶 + 部位 AND。
- 先验：`tests/domain.test.js` 的风格（纯数据 in/out）。覆盖率收集把动作目录模块加进去；**不要**把目录逻辑写进 `domain.js` 来蹭现有门槛。
- 不测：WXML 弹层、CloudBase 上传/下载、页面生命周期、`wx.*`。
- domain 既有用例保持绿：volume 对 `body weight` 与非自重原值的口径不变。

## Out of Scope

- 用户自建动作、收藏、自定义中文名编辑。
- 今天页 / 计划清单 / 记录页 / 历史详情的媒体；动作库列表 JPEG 缩略图已由后续精选目录 ticket 纳入。
- 流畅跟练视频、独立肌肉解剖图、次要肌群展示。
- 热链 GitHub / jsDelivr；把动作目录放到云数据库。
- 改 volume 口径；把 assisted 当成自重动作计总次数。
- Gym visual 书面授权流程本身（发布前待办，不是本 feature 的完成条件）。
- 社区中文名全量人工校对（本轮只覆盖原 30 条）。
- 组间休息计时器、趋势图 top weight / 1RM（既有 MVP 范围外）。
