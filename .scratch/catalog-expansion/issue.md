# 动作库扩容至 136 条、热身标签、v3 计划迁移与媒体同步

**Spec 来源**：`.scratch/catalog-expansion/issues/01-final-catalog-and-generation-chain.md`（execution record）。
本 issue 只描述需求与验收；精确白名单与逐条元数据以 `data/curated-catalog.js` 的 `CURATED_EXERCISES` 为唯一权威。

## Problem Statement

当前精选目录 104 条，已覆盖多数高频动作，但仍有明确缺口：

1. 自重谱不完整：缺少辅助引体、辅助双杠臂屈伸、肩胛引体、靠墙俯卧撑等辅助/退阶动作。
2. 核心模式不完整：缺少站姿绳索卷腹、绳索侧卷腹、站姿哑铃侧屈、悬垂直腿举腿、抗旋转 Pallof 推、交替触肩。
3. 单侧/髋铰链缺口：缺少单腿硬拉、哑铃箭步蹲、反向箭步蹲、农夫行走。
4. 热身/激活无入口：肩袖内外旋、肩胛前伸/后缩、弹力带拉开、Y 字举、肩绕环、髋外展激活、世界最伟大拉伸
   等高频热身动作没有可发现的标签；现有 4 条热身动作（0233/0276/0628/0705）也没有标签入口。
5. 既有条目的 mode/name 存在失真：飞鸟类误用 `horizontal-push`；`0464` 上游是 `front plank with twist`
   却展示为“平板支撑”；`0472` 上游说明书是双腿伸直却存在被当作“屈膝”理解的偏差；
   `0314` 展示名与上游 `incline bench press` 不符；`0196` 带附件赘词。
6. 别名不可检索：`aliases` 在领域词汇表里有定义，但生成链与搜索都没有实现，用户搜“倒蹬/龙门架/下拉”找不到动作。
7. 计划迁移与媒体同步按旧 104 条目录固化，需要随最终 136 条目录升到 v3 并重新同步。

## Solution

把精选目录从 104 条扩容到 **136 条**（公式 `104 − 2 + 34`），并同步修正 mode/tag/name/aliases、
新增第 10 个产品标签「热身」、升级计划迁移到 v3、重新规划 CloudBase 媒体同步。

- **删除 2 条**：`0200`（纯附件重复的绳索下压）、`0673`（反握器械下拉）。
- **保留**：用户最终决定保留 `0227 / 0297 / 0310 / 0333`。
- **新增与恢复 34 条**：
  - B.1 正式新增 28 条：`0009 0017 0216 0223 0226 0235 0246 0336 0381 0407 0437 0475 0575 0710 0864 0979 0993 1361 1604 1757 2133 2188 2616 3006 3012 3021 3561 3699`；
  - B.2 追加新增 6 条：`2143 1017 3011 0688 0624 0659`。
- **严格排除 9 条**：`1015 0222 2399 3697 0549 2571 1419 1314 0241`，不进入最终目录，也不计入数量公式。
- **热身标签 18 条**：既有 `0233 0276 0628 0705` + 新增 `0216 0235 0710 0864 0993 1604 3006 3012 3021 3561`
  + 追加 `2143 1017 3011 0688`。`0464 0979 3699 0624 0659` **不标热身**。
- **筛选顺序 11 项**：`全部 / 胸 / 背 / 肩 / 二头肌 / 三头肌 / 腿 / 腰腹 / 臀 / 热身 / 复合动作`。
- **生成器粗筛放行**：`TARGET_WHITELIST` 增加 `traps`、`serratus anterior`（14 → 16），仍不收耸肩 `0095/0406`、不新增前臂专项。
- **迁移 v3**：`PLAN_MIGRATION_VERSION` 2 → 3，按最终目录可查性直接裁剪，**不建立旧 ID → 新 ID 的 replacement 映射**。
- **媒体同步**：只同步最终 136 条引用的 JPEG/GIF（272 个受管对象），删除范围严格限于 `exercises/images`、`exercises/videos`。
  真实 CloudBase 上传/删除与微信开发者工具渲染仍为人工验收项。

## User Stories

1. 作为训练者，我想在动作库里看到 136 条健身房常用动作，不必在上游全量目录里翻找。
2. 作为训练者，我想按热身标签单独发现肩袖激活、肩胛控制、髋部活动度等准备动作，以便在训练前快速准备。
3. 作为训练者，我想热身动作同时保留具体部位标签，以便我从「肩」或「臀」筛选里也能看到它们。
4. 作为训练者，我想用「倒蹬」「龙门架」「下拉」「澳式引体」等健身房俗称搜到动作，而不是只能搜规范名。
5. 作为训练者，我想自重动作有「标准 + 辅助 + 退阶」的完整链条，以便按当前能力选动作。
6. 作为训练者，我想单侧腿与髋铰链动作（单腿硬拉、箭步蹲、反向箭步蹲）齐备，以便安排腿日和臀日。
7. 作为训练者，我想看到诚实的动作名（带转体的平板支撑不叫普通平板支撑），以便不被展示名误导。
8. 作为训练者，我想升级后计划里的 `0200/0673` 被自动移除，空训练日和空计划被清理，游标仍指向可用训练日。
9. 作为训练者，我想历史记录完全不变，目录裁剪不会改写我已完成的训练。
10. 作为目录维护者，我想最终清单是精确 ID + 可审计元数据，规模与模式分布可被测试复核。
11. 作为目录维护者，我想媒体同步只动受管前缀，且失败可重试、可报告。
12. 作为目录维护者，我想领域文档（CONTEXT/spec/ADR/README）与 136 条目录、11 个筛选一致。

## Implementation Decisions

- 最终白名单与逐条元数据以 `data/curated-catalog.js` 的 `CURATED_EXERCISES` 为唯一权威（136 行）；
  它与离线目录 `data/exercises.js` 必须一一对应（136 = 136）。
- 精选元数据继续是筛选与复合标记的唯一来源，不用上游 `bodyPart` 字段。
- 产品标签新增 `warm-up`（中文「热身」），且必须与至少一个具体部位标签重叠；`compound` 保持重叠标签语义。
- `aliases` 成为生成链的一等字段：`scripts/hand-overrides.js` 承载 nameZh + aliases，`scripts/build-exercises.js`
  写入目录，`data/exercises.js` 的搜索命中 aliases；别名不参与筛选、不改变展示名。
- `TARGET_WHITELIST` 增加 `traps`、`serratus anterior`；`CURATED_EXERCISES` 仍是最终目录唯一闸门，
  放行粗筛不会自动收录耸肩或前臂动作。
- v3 迁移是可用性裁剪，不是 replacement 表：`0200/0673` 及任何非最终白名单动作直接从计划移除。
- 迁移沿用既有安全模型：本地写穿先落定，云端同步独立记版本、可重试、幂等；Session 零写入。
- 媒体同步保持 allowlist 驱动：先校验源路径与符号链接，再上传缺失、校验最终集合、最后删除受管前缀内的陈旧对象。
- 不改变 Plan/Session 结构、主键格式与 `equipment === 'body weight'` 的 volume 口径。

## Testing Decisions

- 主 seam 仍是离线目录模块 `data/exercises.js`（目录/搜索/标签）与 `data/curated-catalog.js`（元数据）。
- 目录测试断言可观察行为：136 条与白名单一一对应；`0200/0673` 与 9 条排除 ID 不存在；34 条新增可 `findById`；
  nameZh 冻结值；11 个筛选各自非空；`warm-up` 结果都与具体部位重叠；复合与具体部位重叠；关键词/器械/部位 AND 不变。
- 别名测试断言用俗称（如「倒蹬」「龙门架」「下拉」「澳式引体」）能搜到对应 ID。
- 迁移测试覆盖 v3 版本号、`0200/0673` 从计划移除、空训练日/空计划删除、游标环回、Session 零写入、离线恢复、幂等。
- 媒体脚本测试覆盖最终目录白名单（272 个对象）、路径安全、受管前缀删除边界、最终集合校验与失败重试。
- 页面级分页测试更新为 `resultCount = 136`，并覆盖 11 个筛选的渲染窗口与 JPEG fileID。
- 微信开发者工具真实渲染/滚动与真实 CloudBase 最终集合、陈旧媒体清理是人工验收 seam，不由 mock 或 dry-run 代替。

## Out of Scope

- 自定义上游不存在的动作（杠铃臀推/臀冲、蚌式开合、弹力带侧步走、静蹲、髋飞机等）或伪造四位 ID。
- 收录耸肩 `0095/0406`、凳上反屈伸 `0129`、前臂专项、平衡设备/版本号/性别后缀/爆发类变式。
- 收录 D 节严格排除的 9 条 ID。
- 改变动作主键、Session 快照结构、volume 计算或历史记录 schema。
- 为三分化/四分化/五分化建立互相独立的目录。
- 自动改写用户计划以注入新增动作（新增动作由用户自行添加）。
- 公开再分发 Gym visual 媒体；ADR-0007 的个人自用与署名约束不变。
