## 整场完成公开接口

03 提供 `queue.complete(session, now = Date.now())`：

- 返回 Promise，resolve 为保留实际组结果、固定 `submittedAt`、移除临时训练控制的完成场次。
- 只有规格门禁通过才接受。相同 session id 重复调用返回原已完成场次，不重复入队或推进。
- 本地成立后立即 resolve，不等待云端读取、联网探测、场次上传或计划同步。
- 本地首次提交写入失败则 reject；保留原草稿，不推进计划、不显示完成小结。
- 网络重试只同步已经成立的结果，不再计算或推进游标。

02 在 `onFinish` 入口同步上锁，直至小结渲染完毕；期间输入、增删、加练、暂停和生命周期不得覆盖提交中的快照。小结使用 `queue.complete` 返回的完成场次；历史比较读取失败不得阻塞本地完成。页面隐藏/销毁后不得重新激活计时器、提醒或打卡按钮。

## 本地持久化建议

现有 `queue.push()` 等待 `flush()`，且 `advancePlanCursor()` 先读云端，不能用于要求本地即时完成的新入口。

为覆盖多键写入失败与进程重启，优先使用**一个逐组完成日志键**：一次同步写入保存完成场次、当时计划推进结果、同步状态；以该写入作为本地完成提交点。后续草稿删除和云同步不是提交点。

- 读取计划时合并尚未同步的推进结果，避免旧云端游标覆盖离线进度；不改目录 v5 迁移规则。
- 记录读取合并本地完成与云端记录，按稳定 session id 去重；不迁移或补写旧历史。
- 队列读取包含未同步完成记录，保留旧队列兼容；同步成功后仅更新日志同步标记，不能删除唯一的本地历史副本。
- 已完成 id 的残留草稿不得重新打卡或重复提交；今天/训练/加练入口识别完成日志，草稿删除失败可以恢复清理。
- 新云端场次用稳定 session id 幂等写入；保留本地完成时间，重试不改总时长。

不引入通用事务框架、依赖或每组联网。实际字段和最小函数拆分由 03 定义，补充至 `implementation.md` 的提交接口节，并以公开边界测试验证。
