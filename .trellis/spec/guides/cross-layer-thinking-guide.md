# 跨层思维指南

> **目的**:实现之前先梳理清楚跨层的数据流。

---

## 问题所在

**大多数 bug 发生在层与层的边界处**,而不是层内部。

常见的跨层 bug:

- 云数据库返回格式 A,页面/domain 层期望格式 B
- 本地缓存存的是 X,同步到云端时转成了 Y,丢了字段
- 多个层各自实现了一遍同样的逻辑,行为逐渐分叉

本项目的典型分层:`wx.cloud` 云数据库 ↔ `utils/db.js`(归一化 + 本地缓存降级)↔ `utils/domain.js`(纯业务逻辑)↔ `pages/**/*.js`(视图模型组装)↔ WXML(纯展示)。

---

## 实现跨层功能前

### 第一步:画出数据流

```
来源 → 转换 → 存储 → 读取 → 转换 → 展示
```

对每一段箭头都问:

- 数据是什么格式?
- 哪里可能出错?
- 谁负责校验?

### 第二步:识别边界

| 边界 | 常见问题 |
| --------------------- | --------------------------------- |
| CloudBase ↔ `utils/db.js` | 字段命名不一致(`_id` vs `id`)、缺字段 |
| `utils/db.js` ↔ 本地缓存 | 格式转换、空值处理 |
| `utils/domain.js` ↔ 页面 JS | 领域对象 vs 视图模型,谁负责派生字段 |
| 页面 JS ↔ WXML | 传给模板的字段是否已经格式化好 |

### 第三步:明确契约

对每个边界:

- 输入格式具体是什么?
- 输出格式具体是什么?
- 可能出现哪些异常?

---

## 常见跨层错误

### 错误 1:隐式格式假设

**差**:不做检查就假设日期/字段格式

**好**:在边界处做显式转换,例如 `utils/db.js` 的 `normalizePlan()` 统一把云端原始文档转成本项目内部的 Plan 形状(`_id` → `id`,缺失字段兜默认值)

### 错误 2:校验散落各处

**差**:同一个校验在多个层各写一遍

**好**:在入口处校验一次,例如 `domain.js` 里的函数统一在开头做 `if (!plan || ...)` 前置判断,调用方不用重复判断

### 错误 3:抽象泄漏

**差**:页面 JS 直接知道 CloudBase 集合结构、直接调 `wx.cloud.database()`

**好**:页面只认识 `utils/db.js` 暴露的仓库方法(`fetchPlans`、`savePlan` 等),不关心云端还是本地缓存

### 错误 4:多处各自解析同一份数据

**差**:多个页面各自从原始 session/plan 对象里手动拼装展示字段

**好**:统一的派生逻辑放进 `utils/domain.js` 或页面自己的 `buildView()`/`renderExercises()` 方法,不要在两个页面各写一遍同样的字段拼装逻辑

## 跨层功能检查清单

实现前:

- [ ] 画出完整的数据流
- [ ] 识别所有层边界
- [ ] 明确每个边界的数据格式
- [ ] 确定校验发生在哪一层

实现后:

- [ ] 用边界情况测试过(null、空、非法值)
- [ ] 验证了每个边界的错误处理(云端失败是否降级到本地?)
- [ ] 检查数据经过"本地写穿 → 云端同步"后没有丢字段
- [ ] 检查新增字段时,`normalizePlan()`/`buildSeedPlan()`/测试夹具是否同步更新
