# 代码复用思维指南

> **目的**:写新代码前先停下来想一想——是不是已经有了?

---

## 问题所在

**重复代码是不一致 bug 的头号来源。**

复制粘贴或重写已有逻辑时:
- 修 bug 时容易漏改某一处
- 行为随时间逐渐分叉
- 代码库越来越难懂

---

## 写新代码之前

### 第一步:先搜索

```bash
# 搜索相似的函数名
grep -r "functionName" .

# 搜索相似的逻辑关键词
grep -r "关键词" .
```

### 第二步:问自己这些问题

| 问题 | 如果答案是「是」... |
|----------|-----------|
| 是否已有类似函数? | 直接用,或者扩展它 |
| 这个模式在别处也用过吗? | 跟随既有模式 |
| 这段逻辑能不能做成共享工具? | 放到合适的位置(如 `utils/domain.js` 或 `utils/format.js`) |
| 是不是在从别的文件抄代码? | **停下来**——应该抽取成共享代码 |

---

## 常见重复模式

### 模式 1:复制粘贴函数

**差**:把一个校验/格式化函数复制到另一个文件

**好**:抽到 `utils/format.js` 或 `utils/domain.js`,在需要的地方 `require` 进来

### 模式 2:相似的页面逻辑

**差**:新建一个和现有页面 80% 相似的页面处理逻辑

**好**:复用 `app.wxss` 里已有的通用 class(`.primary-button`、`.section-kicker` 等),复用 `utils/domain.js` 里已有的纯函数

### 模式 3:重复的常量

**差**:同一个本地存储 key 字符串在多个文件里各写一遍

**好**:定义成常量放在使用它的模块顶部并统一 `require`,例如 `TRAINING_DRAFT_KEY`、`LOCAL_KEYS`

### 模式 4:重复的字段提取/格式化逻辑

**差**:多个页面各自手写日期拼接、数字千分位、时长格式化

**好**:统一走 `utils/format.js` 的 `formatDateLine`/`formatNumber`/`formatDuration`,新页面需要同类格式化时先检查这个文件有没有现成的

---

## 什么时候该抽象

**该抽象的情况**:
- 同样的代码出现 3 次以上
- 逻辑复杂到容易出 bug
- 多个页面/场景都可能用到

**不该抽象的情况**:
- 只用一次
- 是简单的一行代码
- 抽象出来反而比直接写更复杂

---

## 批量修改之后

对多个文件做了类似修改后:

1. **回顾**:是不是所有该改的地方都改了?
2. **搜索**:跑一遍 `grep` 确认没漏改
3. **考虑**:这段逻辑是不是该抽象成共享函数了?

---

## 提交前检查清单

- [ ] 搜索过是否已有类似代码
- [ ] 没有应该共享却复制粘贴的逻辑
- [ ] 没有在多处重复实现同一种格式化/校验
- [ ] 常量只定义在一处
- [ ] 相似模式遵循相同的结构(如页面的 `refresh()` + `buildView()` 组合)
