# ADR-0010：逐组显式结果与整场本地完成

- 状态：已采纳；实施与验收状态见逐组训练 issue
- 相关文档：[逐组规格](../../.scratch/set-by-set-training/spec.md)、[领域契约](../../.scratch/set-by-set-training/implementation.md)、[并行提交契约](../../.scratch/set-by-set-training/integration-contract.md)

## Context（背景）

原快照预填 `{weight, reps}`，无法区别计划目标、真实完成和部分跳过；修改既有历史去补状态会伪造当时的训练。训练页下标随着加练、删组变化，不能用它持久化当前组。旧提交入口等待网络冲刷，且本地场次、计划游标、草稿属于多个存储键，部分写入失败或重启可能导致重复推进。

## Decision（决策）

- 新快照与动作加 `flowVersion: 1`；每组用场次内稳定 `id` 与 `pending / completed / skipped` 显式结果。控制阶段和组结果分开，预填或填写不触发完成。
- 只显式升级进行中的本地旧草稿，保留输入和旧跳过；旧已提交历史不迁移、统计不变。新增组统一 pending，不将缺状态的新组当旧已完成组。
- 实际统计仍唯一位于 domain：新流程只计 completed，自重只认 `body weight`；部分跳过不抹掉完成成绩。最终快照保留结果，移除草稿临时控制。
- 间歇使用绝对截止时间；主动暂停冻结，隐藏不冻结。业务状态先成功持久化，再补一次前台提醒；声音失败不阻塞。运行时 timer / 音频不进入快照。
- 整场完成采用独立本地提交点，持久化完成场次与计划推进结果。成功后本地结果成立；云同步、草稿清理不是完成前置条件。重复调用、残留草稿、队列重试均不重复推进。
- 新云端场次使用稳定 session id 幂等写入，固定本地完成时间；不扩大数据库权限。离线历史与未同步计划推进从持久化结果读取，不被旧云端数据覆盖。
- 更新 ADR-0003 的“唯一测试 seam”限制：domain 仍是核心规则纯函数边界，新增 Page 用户事件 / 生命周期、记录与提交队列公开边界测试，仅 mock `wx` / 云端 / 时间 / 存储。自动测试不能替代 WXML 或真机验收。

## Consequences（后果）

- 新旧记录并存，需要显式版本与组结果筛选；兼容分支留在 domain，历史读取不能调用草稿升级。
- 本地完成日志保存不可丢弃的离线历史及未同步推进结果；完成写入失败可重试，云端失败不回滚本地完成。
- 没有后台准时通知或音频保活保证；真机声音、静音、振动、锁屏恢复仍是独立验收项。

ADR-0004 的快照解耦和历史不可变、ADR-0005 的离线优先原则保留；旧“整项跳过全排除”和“提交驱动推进”由本 ADR 对新流程细化为“逐组结果”和“本地整场完成驱动推进”。
