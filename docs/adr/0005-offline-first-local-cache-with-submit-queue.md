# ADR-0005：离线优先——全程本地缓存，结束时提交 + 队列重试

- 状态：已采纳
- 日期：2026-09-17
- 相关文档：`docs/spec.md`（打卡流程）、`docs/spec-mvp.md`

## Context（背景）

真实使用场景是健身房：地下室、器械区、更衣室，**网络经常不可用**。
而训练过程中用户注意力在动作和休息上，不可能容忍"每填一组就转圈等网络"。

反过来，训练记录又必须最终落到云端（换设备、重装小程序后不能丢），
所以不能做成纯本地应用。

## Decision（决策）

**训练全程走本地缓存，只在"完成训练并提交"那一刻联网**，失败则排队重试。

- 打卡期间草稿与每一组数据写入小程序本地存储，UI 只操作本地状态，**不发网络请求**。
- 点击"完成训练并提交"时才触发一次写入：
  `utils/queue.js` → `push(session)` → 入队（本地记录立即成立）→ `flush()`。
- 网络判定与重试策略：
  - `wx.getNetworkType` 判在线；拿不到状态时按"有网"尝试，失败自然进入重试。
  - 无网 → `decideSubmission` 返回 `queued`，队列持久化在 `wx.getStorageSync('fitness:pendingQueue')`。
  - `wx.onNetworkStatusChange` 监听网络恢复，自动 `flush`；另有兜底定时重试（`RETRY_DELAY_MS * 4`）。
  - 提交失败 `attempts + 1` 保留在队列，等待下轮重试。
- 判定逻辑（`decideSubmission` 等）是**纯函数**，位于 `utils/domain.js`；
  真实网络请求由 `utils/queue.js` 注入 `db.submitSession()`。

## Consequences（后果）

**正向**

- 训练现场零网络依赖，打卡体验不受信号影响。
- 本地记录先成立，网络失败不丢数据。
- 判定逻辑可单测（注入假队列 + 假在线状态），不需要模拟网络。

**代价 / 需要接受**

- 存在"本地已记录、云端未同步"的中间态：换设备前若队列未清空，记录不会出现在新设备。
- 队列重试没有 UI 可见的同步状态提示，失败对用户不可见（MVP 阶段接受）。
- 若同一 session 重复提交（例如成功但响应丢失），需要后端幂等或前端按 `id` 去重。

**缓解措施**

- `enqueueSession` 幂等：同 `id` 不重复入队。
- 队列与草稿分开存储（`fitness:pendingQueue` vs 计划缓存），互不覆盖。
