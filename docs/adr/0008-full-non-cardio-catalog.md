# ADR-0008：发布目录改为非 cardio 可用全量，筛选改官方原值

动作库不再用精选白名单做发布闸门，改为上游非 cardio 全量减去锁定媒体排除清单；筛选只认 `bodyPart` 与 `equipment` 原值。精选 tags、器械归并桶和目标肌群粗筛无法覆盖约千条目录，且与「按官方分类筛选」冲突。主键、离线文本分片、CloudBase 媒体、`exerciseId` 反查仍沿用 ADR-0007。

- 状态：已采纳
- 日期：2026-09-21
- 相关文档：`docs/spec.md`、`CONTEXT.md`、ADR-0007（主键与媒体托管仍有效，目录范围与筛选被本文取代）

## Context（背景）

ADR-0007 把数据源定为 hasaneyldrm/exercises-dataset，但发布目录锁在精选白名单（当时 125 条），筛选走手写部位标签与 6 个器械归并桶。产品要「全部非有氧动作 + 官方身体部位/器械分类」。手写 `mode/tags/compound` 不能扩到全量；上游 `body_part` 有封闭枚举，`equipment` 没有封闭枚举，只能扫实际值。

## Decision（决策）

1. **发布目录** = 上游 `body_part !== cardio` 减去锁定排除清单（源 JPEG/GIF 或中文要领缺失的 id）。耸肩、前臂、平衡设备、爆发变式一律放行。
2. **筛选**只匹配原值：部位 9 类官方 `body_part`；器械为目录内实际 `equipment`，稳定排序。胶囊多选，组内 OR，与搜索 AND。退役精选标签与归并桶。
3. **中文名**仍用社区映射 + 手译覆盖。闸门是 id 唯一且 nameZh 非空，允许中文名碰撞。
4. **媒体可访问**以本地源目录文件存在为准，不以 JSON 路径非空为准。无源目录则生成失败。
5. **扩容不升计划迁移版本**，不删现有计划动作。真实 CloudBase 全量上传仍人工门控。

## Considered Options（考虑过）

- **继续精选 100–140 条**：加练找不到上游已有动作，且筛选对不上官方分类。
- **保留产品标签并规则推导**：二头/三头/臀/热身不是上游 `body_part`，全量规则易漂，与「仅官方原值」冲突。
- **缺媒体仍进目录再降级**：会出现能搜到但详情空洞的条目。
- **目录改云端加载**：主包更瘦，但破坏健身房离线加练。

## Consequences（后果）

**正向**

- 加练范围与数据集非有氧部分对齐；筛选可对照官方 `body_part` 与实际器械。
- 不再维护千条手写 tags。

**代价**

- 主包文本与 CloudBase 对象从约 125×2 升到约可用全量×2；体积实测与真实上传仍待办。
- 列表变长，重复英文名/中文名会同时出现。
- 热身/复合/二头三头等产品入口消失，只能靠部位原值、器械原值和搜索（含别名）。
