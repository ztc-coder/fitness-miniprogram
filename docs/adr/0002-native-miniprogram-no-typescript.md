# ADR-0002：前端使用微信原生小程序，不引入 TypeScript / 跨端框架

- 状态：已采纳
- 日期：2026-09-17
- 相关文档：`docs/spec.md`、`docs/spec-mvp.md`

## Context（背景）

项目是个人自用、只发布到微信小程序，没有多端（App / H5 / 支付宝小程序）诉求。
可选项有三类：

1. 微信原生（WXML / WXSS / JS）
2. 原生 + TypeScript
3. 跨端框架（Taro / uni-app）

跨端框架与 TS 都会引入构建链路（编译、依赖版本、插件兼容），
而本项目没有多端需求、没有团队协作规模，构建链路带来的复杂度缺少对应的收益。

## Decision（决策）

前端使用**微信原生小程序**（WXML / WXSS / JS），**不引入 TypeScript、不引入跨端框架**。

- 无构建步骤：微信开发者工具直接运行仓库源码。
- 页面结构：4 个 tab（今天 / 计划 / 记录 / 我的）+ 4 个非 tab 页。
- 唯一工具链是测试用的 Jest（`devDependencies` 只有 `jest`），且只作用于纯逻辑模块。

## Consequences（后果）

**正向**

- 无编译产物，调试链路最短，`app.json` / 页面文件即最终运行物。
- 无框架抽象层，微信官方文档与代码一一对应，排错成本低。
- 依赖极少，包体与安全面都更可控。

**代价 / 需要接受**

- 没有静态类型，字段拼写错误只能在运行时或测试中暴露。
- 未来若要做多端，需要重写视图层。
- 缺少框架提供的状态管理，跨页共享依赖 `app.globalData` 与本地存储。

**缓解措施**

- 把容易出错的规则（游标推进、快照复制、volume、队列判定）集中到 `utils/domain.js` 并用 Jest 覆盖，
  以测试替代类型系统兜住核心逻辑（见 ADR-0003）。
- 数据模型在 `CONTEXT.md` 中固定为文档契约，代码变更需同步更新。
