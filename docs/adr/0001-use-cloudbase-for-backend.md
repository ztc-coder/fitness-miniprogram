# ADR-0001：后端使用微信云开发 CloudBase

- 状态：已采纳
- 日期：2026-09-17
- 相关文档：`docs/spec.md`、`docs/spec-mvp.md`

## Context（背景）

项目是个人自用的单用户闭环工具，没有多角色、支付、通知等需求，也不存在运营团队。
如果自建后端（服务器 + 数据库 + 部署链路），需要长期承担运维、域名、备案、证书、监控等成本，
而收益仅仅是"可控性"，对单人维护的项目是明显的投入产出倒挂。

同时训练数据是**个人训练记录**，天然的权限边界是"只有自己能读写"，与微信账号身份天然对齐。

## Decision（决策）

后端使用**微信云开发 CloudBase**：云数据库 + 云存储 + 云函数，免运维。

- 云数据库集合：`plans`、`sessions`，权限设为「仅创建者可读写」。
- 云函数：`cloudfunctions/login`，只做静默 openid 登录。
- 云存储：承载动作图片与 GIF，按需加载，不进主包。
- 环境 ID 配置在 `app.js` 顶部常量 `ENV_ID`。

## Consequences（后果）

**正向**

- 零运维，无服务器/域名/证书维护成本。
- openid 天然成为用户标识，无需自建账号体系与登录墙。
- 云数据库 + 云存储 + 云函数同一套 SDK，前端直连，省掉 API 层。

**代价 / 需要接受**

- 绑定微信生态，未来若要做 Web 端或跨端需要重做数据访问层。
- 云开发有配额与冷启动特性，查询能力弱于自建 SQL（无复杂聚合、无 join）。
- 本地开发依赖微信开发者工具；测试只能覆盖不依赖运行时的纯逻辑层（见 ADR-0003）。

**缓解措施**

- 数据访问全部收敛到 `utils/db.js`（仓库模式），页面不直接触碰 SDK；
  未来替换后端时只需重写这一层。
- 云端读取失败降级到 `wx.getStorageSync` 本地缓存，保证离线可用。
